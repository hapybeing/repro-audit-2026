## Limitations (read first)
- Small sample: n = 5 papers (batches/batch3_counts_rule4.json). These counts support no rate claims about any journal, field or repository.
- The two agents are not independent human replications. Agents A and B are separate runs with no shared context, but they use the same underlying model family, so they can share blind spots.
- Process notes on blinding. The agents ran at the same time in one shared workspace. On 12_CYBR7L, agent B, while checking whether a pip install had finished, saw one agent A process command line (a pandas reinstall) in a `ps aux` listing; it read no A file and stopped using ps (papers/12_CYBR7L/B/LOG.md). The sandbox tool also printed the names of files other agents had changed after some commands, so B agents saw some A file names as change notices; they report not opening any A folder (papers/11_DDOFPS/B/LOG.md, papers/15_1BBC4E/B/LOG.md).
- 11_DDOFPS: SciELO answers scripted downloads with HTTP 403 (bot challenge), so the paper was read during pre-registration through a browser print of the PDF and the HTML page (papers/11_DDOFPS/PREREG.md). Agent B did not re-read the paper and took the paper values from PREREG.md (papers/11_DDOFPS/B/results.json).
- 13_DX5T9G: the online supporting information was not read; no target comes from it (papers/13_DX5T9G/PREREG.md). The regenerated Tables 2 and 3 match the printed values in all 20 WHO cells; on three non-target cells of Table 2 they print significance stars that the published table does not show or shows differently. Values match; only the stars differ (papers/13_DX5T9G/A/results.json).
- 13_DX5T9G: the full deposited pipeline could not finish on the audit's shared 7 GB machine, so the targets come from a fallback pre-registered before any run (batches/batch3_class_rules.json; section 13_DX5T9G below).
- 15_1BBC4E: the publisher's supplemental appendix could not be read (HTTP 403 by script); no target comes from it (papers/15_1BBC4E/PREREG.md).
- Package versions: 11_DDOFPS and 15_1BBC4E pin none, so current CRAN and Debian versions were used; 13_DX5T9G ran on R 4.5.0 against the authors' 4.2.2 (papers/13_DX5T9G/A/results.json); on 14_CJISMY the authors' dplyr and vctrs pins could not be loaded (sections below).
- Robustness: pre-registered checks show fragile results in two papers. In 11_DDOFPS the over-time increase of the correlation reverses under Spearman and shrinks after outlier exclusion; in 14_CJISMY the main estimate loses significance without country fixed effects (batches/batch3_results_rule4.csv). Robustness never changes a class (PROTOCOL.md section 7). The 12_CYBR7L paper reports no significance test, so the p-values the agents computed for its checks are information only.
- Absence searches can show absence only within what they searched (papers/11_DDOFPS/ABSENCE_SEARCHES.md, papers/14_CJISMY/ABSENCE_SEARCHES.md).
- No author was contacted. An alternative class C or E means "could not be fully checked from the materials as deposited" under that reading. It does not mean the paper is wrong.

## Plain-language summary
All five randomly drawn papers in this batch reproduced from the deposited materials: every pre-registered number matched the paper at its printed rounding, in two blind runs that agreed with each other exactly. A clean result like this is itself a finding. Two papers needed a judgement that could be read the other way: in one, the deposit names its input files differently from the script; in another, the full pipeline did not fit in the audit machine's memory, so a shortcut fixed before any run, with the same estimation steps, was used. In two papers a pre-registered robustness check weakens a result: one paper's correlation does not clearly grow over time under a rank correlation, and one paper's main estimate loses significance without country fixed effects. One coding slip was verified, in a footnote model that touches no headline estimate. None of this says any paper is wrong: these are statements about what the deposited materials allow an outsider to check.
