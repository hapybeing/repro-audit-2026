# Batch 2 classification decisions (fixed before any batch 2 reproduction run)

Written 2026-10-10 (IST) after the five pre-registrations and before any of the authors' analysis code was run. Frozen with the pre-registrations in batch2_prereg_hashes.txt. Applies PROTOCOL.md section 7 and CHANGELOG_METHOD.md #4 exactly as in batch 1; nothing here changes those rules, it only records how they apply to cases the batch 2 pre-registrations raised.

1. Rule 4 with no data statement (10_6MLKJZ). Materials are the deposit plus every location the article's statement names. With no statement, materials are the deposit alone. If the deposit holds every file the code reads, the paper is judged on its reproduction like any other. (Paper 04 in batch 1 was C because its deposit lacked the data, not because the statement was missing.)

2. Restricted data at a location the statement names (09_4U8CTG, Study 1). The audit does not sign in or register anywhere (PROTOCOL.md section 9). Targets whose inputs sit only behind registration count as "materials not available to the audit", so the paper's main class is C. The class computed on the openly available targets alone (T1 to T4, Study 2) is reported as the alternative, in the same way as batch 1's alternatives.

3. No printed headline estimates (10_6MLKJZ). Numeric targets are the Table 2 sample sizes. A requires every N target exact and figure-claim checks FC1 to FC3 to hold as pre-registered. B requires every N within 5% and FC1 to FC3 to hold. An FC that fails in both A and B clean runs is a D candidate; one that fails in only one run is flagged, not resolved.

4. Targets read from a supplement because the main text could not be read (07_JH9DBC). The paper is classified on those targets, and the report states that the main article's Table 2 was not compared.

5. Thresholds near p = 0.05 (06 T1/T4, 09 T1). The paper value and conclusion criteria are as pre-registered; a reproduced value that matches to rounding is a match even if the computed p falls on the other side of 0.05, and that is reported as a note.

6. Robustness checks never change the class (PROTOCOL.md section 7).
