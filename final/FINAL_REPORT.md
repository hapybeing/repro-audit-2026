# Reproducibility audit of 25 papers: final report (v1.0)

Audit by Gaurang Kumar (@hapybeing). Analysis carried out with Hark. Generated by `scripts/make_final.py` from the published batch files; every number is checked against its source file by `scripts/check_final_numbers.py` (`final/FINAL_number_check.txt`). Counts only: n = 25 is small, so no rates are given.

## Summary
Twenty-five papers were drawn at random from 2023 to 2026 Harvard Dataverse deposits that contain R or Python code (SELECTION.md), and each was re-run from the authors' deposited materials by two blind agent runs against pre-registered targets. Main counts: A 16, B 0, C 9, D 0, E 0 (n = 25; final/all25_counts.json). With every paper's alternative reading at once: A 13, B 3, C 5, D 1, E 2 (n = 24, one paper's alternative being exclusion; final/all25_counts.json). Both agent runs proposed the same class for 25 of 25 papers and agreed on every target value both computed in 25 (22 papers had at least one computed target; final/all25_counts.json). Of 139 pre-registered targets, 126 could be computed and 122 matched the paper at its printed rounding in both runs (final/all25_counts.json). No paper is class D under the main reading. Class C means a paper could not be fully checked from the materials as deposited; it does not mean the paper is wrong.

## What the classes mean (PROTOCOL.md section 7)
- A: reproduced exactly (matches to the paper's reported rounding).
- B: reproduced approximately (all headline numbers within 5% relative, same direction and same significance conclusion).
- C: not reproduced, materials incomplete or unclear (missing files, code that cannot produce the reported table, undocumented steps).
- D: not reproduced, discrepancy remains and affects the conclusion. Only if the discrepancy survives both A and B clean runs.
- E: could not run (reason stated, e.g. exceeds compute, missing system dependency that cannot be installed).
- Robustness outcomes are reported separately and never change the class. The materials rule (CHANGELOG_METHOD.md #4): the deposit plus every location the article's own data statement names; locations the audit found itself give only an alternative class.

## How the papers were drawn (SELECTION.md)
- Frame: every Harvard Dataverse dataset released 2023-01-01 to 2026-12-31 with at least one R or Python code file, 8593 datasets, of which 6769 are hosted at Harvard (SELECTION.md).
- Random order: Harvard-hosted rows sorted by dataset DOI and permuted with numpy `default_rng(20261009)`; seed 20261009 (SELECTION.md).
- Screening in random order until 25 were eligible: 88 screened (SELECTION.md). Eligibility E1 to E6: one peer-reviewed journal article with a DOI published 2023 to 2026, openly readable article text, no restricted files, no Stata, MATLAB, SPSS or SAS code, at most 5 GB, licence allows use (PROTOCOL.md section 3).
- Data presence was not an eligibility criterion, so the sample is papers whose Dataverse deposit contains R or Python code, not papers with open data and code (SELECTION.md).

## Method
- Two agent runs per paper: agent A and a blind agent B in a separate folder, given only the paper DOI, dataset DOI and PREREG.md. Both use the same underlying model family, so they are not independent human replications (PROTOCOL.md).
- Pre-registration: targets copied from each paper and three robustness checks were frozen and hashed before any run. Batch 1 was frozen locally and first published with its results (self-attested); batches 2 to 5 were pushed and announced in GitHub issues #1 to #4 before any run (CHANGELOG_METHOD.md).
- Three pre-registered robustness checks per paper: (a) another seed or bootstrap resample, (b) excluding extreme outliers, (c) one alternative reasonable analysis choice (PROTOCOL.md).
- Code review: only observations with file and line, a saved output change or data fact, and detection by both agents count as verified; the rest are unverified agent observations and are not findings (CHANGELOG_METHOD.md #4d).
- Classes were set by the lead from saved outputs after both agents reported, using pre-run class decisions for each batch; every alternative reading is reported.

## Why each class C paper is C
One line per paper, from its batch report. Reason types: N-only mismatch 2, data behind registration 1, missing code 1, missing data location 2, no computational target 1, p-only mismatch 1, undocumented sample step 1 (final/all25_counts.json).

- 01_5BIH0P (no computational target): the paper reports no computed number for this deposit, and the production trajectory the deposit's analyses read is not in the collection (batches/batch1_report.md).
- 03_3IOGQ8 (missing data location): the PSM export the notebook reads is not deposited at any location found (batches/batch1_report.md).
- 04_PSHE5L (missing data location): the article has no data statement and cites no external location; the deposit is one R script (data found by the audit on an uncited OSF page) (batches/batch1_report.md).
- 06_VSV5DM (p-only mismatch): every estimate matches; the pre-registered AME p-value does not reproduce the printed value, in the same 0.05 to 0.10 band (batches/batch2_report.md).
- 08_SQRZR8 (N-only mismatch): all five Table 3 coefficients match; the code cannot produce the printed N in the Table 3 note (batches/batch2_report.md).
- 09_4U8CTG (data behind registration): Study 2 targets match; the Study 1 inputs sit behind ELIPSS registration, so Study 1 targets were not run (batches/batch2_report.md). Authors' response (2026-10-13): the Study 1 data are available to any researcher who registers with ELIPSS; the audit did not register under its pre-registered rule (papers/09_4U8CTG/AUTHOR_RESPONSE.md).
- 10_6MLKJZ (undocumented sample step): the deposited code gives a larger general-population total than printed and has no step that removes the extra respondents (batches/batch2_report.md).
- 20_SINIYU (missing code): the one script that computes a paper number imports a module that is not deposited, and no deposited code computes Table 1 (batches/batch4_report.md).
- 21_LEFTNE (N-only mismatch): every estimate target matches; the Table 3 N reproduces one row larger than printed, as the deposited data hold (batches/batch5_report.md).

## Method changes (CHANGELOG_METHOD.md)
- 2026-10-09, #1 (before selection was run; no results existed): frame restricted to datasets hosted on Harvard Dataverse (DOI prefix 10.7910).
- 2026-10-09, #2 (before any paper was selected; no results existed): article DOIs looked up on Crossref by title when Dataverse lists none; failed lookups stop the script instead of counting as ineligible.
- 2026-10-09, #3 (after selection and pre-registration of batch 1; before any reproduction run): PROTOCOL.md restored verbatim after a sandbox recycle; runs moved to Debian system R.
- 2026-10-10, #4 (after batch 1 results; prompted by external review): materials rule (deposit plus locations the article's own data statement names); no-computational-target label; clock deviations; verified versus unverified code observations; exploratory checks labelled.
- 2026-10-10, #5 (after batch 1 results; pre-publication hardening, no class or count changed): scripted absence searches; number checks; status notes on agent logs; pre-registration hashes pushed before runs from batch 2 on.
- 2026-10-10, #6 (after batch 2 results; class readings set by the lead after both blind agents reported): N-only or p-only mismatch with every estimate matching is C, not D (6a); fixest 0.12.1 accepted as an environment fix for 07_JH9DBC (6b); setup script fix (6c).

## Limitations
- Small sample: n = 25 papers from one repository (Harvard Dataverse), and only deposits with R or Python code. The counts support no rate claims about any journal, field or repository (final/all25_counts.json).
- Agent runs, not human replications: A and B share no context but use the same underlying model family, so they can share blind spots (PROTOCOL.md).
- Version substitutions: runs used R 4.5 and, where no versions were pinned, current package releases. Some pinned packages did not build or load, so pre-registered fallbacks or system versions were used (14_CJISMY, 17_T1NXVQ, 25_914AN0), and for 07_JH9DBC the package version of record was chosen after seeing current-version output (batches/batch2_report.md, batches/batch3_report.md, batches/batch4_report.md, batches/batch5_report.md).
- Reduced bootstraps: 17_T1NXVQ significance uses a pre-registered reduced bootstrap with the authors' seeds instead of the full bootstrap (batches/batch4_report.md).
- Target-blocks-only runs and fallbacks: 24_U9CKK6 and 25_914AN0 ran only the target blocks; 13_DX5T9G used a pre-registered fallback after running out of memory; 19_KH0SQ2 used a pre-registered session driver (batches/batch3_report.md, batches/batch4_report.md, batches/batch5_report.md). 24_U9CKK6, 13_DX5T9G and 19_KH0SQ2 each have an alternative class; 25_914AN0 has no alternative class for its targets (batches/batch5_report.md).
- Sandbox restarts interrupted some runs in batches 4 and 5, and a sandbox recycle before the batch 1 runs removed the R environment and PROTOCOL.md, which was restored verbatim (CHANGELOG_METHOD.md #3). Every reported number comes from a process that completed (batches/batch4_report.md, batches/batch5_report.md).
- Batch 1 pre-registration ordering is self-attested: hashes were frozen locally before the runs but first published with the results (CHANGELOG_METHOD.md #5e).
- Post-results reading: CHANGELOG_METHOD.md #6a (an N-only or p-only mismatch with every estimate matching is C, not D) was written after the batch 2 results; counts are shown both ways in batches/batch2_counts_rule4.json, and it also sets the main class of 21_LEFTNE in batch 5, where it was a pre-run decision.
- Some paper values were read from supplements through viewers or screenshots because publishers block scripted downloads; each case is in its batch report. Absence searches show absence only within what they searched.
- No author was contacted during the audit; corresponding authors were notified after publication, on 2026-10-12 (outreach_log.md, AUTHOR_REPLIES.md). A class C or an alternative C or E means the paper could not be fully checked from the materials as deposited under that reading; it is not a judgement of the research.
- Batch 2 freeze file check in the public repository: CHANGELOG_METHOD.md was extended with a later entry after the batch 2 results (the frozen text is still the unchanged start of the file), and the third-party page images and texts listed in batches/batch2_publish_exclusions.tsv are kept out of the public repository, so those files cannot be re-hashed here. Batches 3 to 5 re-hash fully. Details: final/FINAL_prereg_hash_check.txt.
