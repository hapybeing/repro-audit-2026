## What was changed
- Nothing in the authors' code or data. `replication.R`, `analysis_data_creation.R` and the three original CSVs were run byte-identical (sha256 in `A/checksums.sha256`).
- Only the process clock seen by R was changed, with libfaketime (Debian package `faketime` 0.9.10):

  The date 2025-05-06 13:14 is the "Log Start Time" in the authors' `LOG.pdf` (Dataverse file 11182347).

## Why
- `analysis_data_creation.R` line 61 calls `peacesciencer::create_stateyears()` with defaults. In peacesciencer 1.1.0 the default `mry = TRUE` sets the last year of the state-year frame to `as.numeric(format(Sys.Date(), "%Y")) - 1`, so the sample depends on the calendar date of the run.
- Real clock (2026-10-09): frame years 1816 to 2025, 17706 country-years. Authors' run date (2025-05-06): years 1816 to 2024, 17511 country-years, identical to the shipped `d` in `AJPS_analysis_data.RData` (`A/outputs/compare_d_rebuilt_vs_shipped.csv`).
- The added year enters test 1 (M1, all country-years) but no added row has `pub_def == 1`, so test 2 (M2, the main result) is unchanged.
