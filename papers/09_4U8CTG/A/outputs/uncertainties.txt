T5 and T6 (Study 1, FES 2022 panel) were not reproduced: the inputs are not in the deposit and are registration-only at ELIPSS. Whether the Study 1 half of the abstract's claim reproduces is unknown to this audit.
T1 p-value: reproduced two-sided classical OLS p = 0.0461 (t = -2.015), just under 0.05, matching the paper's * mark; the paper's own D8 rounds it to 0.05. A small change in data or method could move it across the threshold (see R_a, R_b, R_c, none of which keeps p < 0.05).
R_b removes 2 control-arm rows with z > 3 on swd_ch (z max 4.21); the T1 estimate then shrinks to -0.54 (p = 0.32). This shows the Model 1 estimate is sensitive to two control-arm observations; it is a pre-registered robustness outcome and does not change the class.
Environment: most R packages are Debian system binaries installed machine-wide by the shared setup (not a fresh per-run library); only texreg, stargazer, vtable, jtools and binom are in the per-run library. No versions are pinned by the authors (README: R 4.1 or higher). All 22 regenerated Study 2 tables are byte-identical to the deposited ones after stripping CR line endings, so version drift did not affect any reported number.
Run 1 of the extraction sourced 02 with source(echo = FALSE), which does not auto-print, so the texreg() tables written via sink() were empty files. Run 2 used print.eval = TRUE (equivalent to running 02 top level with Rscript); target values were identical in both runs (cmp of targets_extracted.csv). This concerns how 02 is invoked, not the authors' analysis.
The dataset API lists 64 files (27 PNG); PREREG.md says 66 files and 29 PNG. All 37 non-image files match the PREREG sha256 values exactly. The count difference was not investigated further.
01_manuscript.R was not run (not required by the PREREG); Figures 3 and 6 were not regenerated or compared.
