## 3. Robustness checks (pre-registered)

Primary quantity for every check: T1, the mean hamming loss of GPT 4o Few Shot 8 labels (written as `estimate` in results.json). Also reported for every check: D = T1 minus the undergraduate 8-label hamming loss (paper: 0.18 - 0.15, "by 0.03 points"), the rank of GPT 4o Few Shot 8 labels among the 18 LLM specifications, and T3 minus T1.

"Same direction and significance as the paper" for every check means all three of: (i) GPT 4o Few Shot 8 labels has the lowest hamming loss of the 18 LLM specifications (point estimate); (ii) D > 0; (iii) the 95% percentile bootstrap interval of D (procedure of R_a, seed 20261010, 1000 resamples, on that check's data) lies entirely above 0. The paper reports no test, so (iii) is the audit's own significance reading and is stated as such.

R_a. Bootstrap resample of articles. From the session objects of the main run, take the row index set 1..n (n = `nrow(pi10mat)`, expected 589). Call `set.seed(20261010)` once (R default RNG: Mersenne-Twister, Inversion, Rejection), then draw 1000 index vectors `idx <- sample(n, n, replace = TRUE)`. For each, apply the same `idx` to `pi10mat`, the nine 8-label LLM matrices, `hum10matx`, `pi4mat`, the nine 4-label LLM matrices and `hum4matx` (this keeps the row pairing exactly as the authors' code has it), and compute each model's hamming loss as the mean over labels of `mean(benchmark[idx, j] != model[idx, j])` (same formula as `calculate_hamming_loss`). Report: original T1 as estimate; 2.5th and 97.5th percentiles of T1 and of D as `se_or_ci`; bootstrap SE of D; p-value = min(1, 2 * share of resamples with D <= 0); share of resamples in which GPT 4o Few Shot 8 labels is the lowest of the 18 LLM specifications (descriptive, no threshold).

R_b. Outlier exclusion. The outcome is a set of binary cells, so |z| on the outcome is meaningless, and the analysis has no continuous predictor. The rule is applied to the one continuous per-article quantity that defines the benchmark: the author's number of labels per article, `k = rowSums(pi10mat)` (0 to 8). Compute z = (k - mean(k)) / sd(k) (sd with n - 1) over the n articles; drop every row with |z| > 3; drop the same row positions from every 8-label and 4-label matrix (LLMs, undergraduates, `pi4mat`), keeping the authors' row pairing; recompute all 18 LLM hamming losses and both undergraduate ones; then run the R_a bootstrap (seed 20261010, 1000 resamples) on the reduced rows for criterion (iii). Report the number of rows dropped. If no row has |z| > 3, report R_b as ran with 0 exclusions (identical to the main result); no other rule is substituted.

R_c. Alternative analysis choice: pair benchmark and model rows by docid. In a copy of the Rmd saved under `scripts/` (never the authors' file), insert exactly one line after line 108: `pi = pi %>% arrange(docid)`. Change nothing else. Rerun the whole copy as in section 2 and extract T1 to T6, D and all 18 + 2 hamming losses with the same extraction script, plus the R_a bootstrap (seed 20261010, 1000 resamples) on the realigned matrices. Before running, record in LOG.md the diagnostic `identical(pi$docid, gpt_data$gpt4o_10lab_fewshot$docid)` and `identical(pi$docid, human_data$human_10lab$docid)` for the original script (expected FALSE from reading the files) and for the copy (expected TRUE). Because pi4 and the actual_list objects are built from `pi` after line 108, the one line realigns every author-benchmark metric. Whether the original order is a bug is for the code review to decide on that evidence; R_c only reports what the alternative pairing gives.

Optional exploratory (not pre-registered, labelled as such per CHANGELOG #4e, never changes the class): reproducing Table A2 by switching to the undergraduate benchmark (lines 133-140 off, 143-150 on).

## 4. Known risks

- Paper numbers: the targets come from a browser agent's reading of the supplement in the Google Docs viewer, not from a downloaded PDF (Sage Cloudflare). T1 and T2 are confirmed by the main text; T3 to T5 rely on that reading only. A digit misread would show as a mismatch in exactly one cell; agents who can open the supplement should re-check the four Table A1 rows in `data_statement_raw/target_rows_excerpt.txt`.
- Missing files: none for the target script. `Benchmarking_DataGeneration.Rmd` needs raw article texts the author withheld (`rnums.csv`, `all_news.csv` (both on commented lines), `full_df_for_classification_ten.csv`, a `text` column absent from `AI_goldstandard_*_v2.csv`, which `Benchmarking_Supplementary.Rmd` also needs for Appendix H, lines 1004 and 1102) plus `batch_part1_output_v2.jsonl` and `batch_part2_output_v2.jsonl`, and a paid API key; it produces the LLM output files, which are deposited. See DATA_STATEMENT.md.
- The 4 undergraduate coder sheets are served by Dataverse as ingested `.tab` files while `Benchmarking_Supplementary.Rmd` and `Benchmarking_DataGeneration.Rmd` read `.csv` names. Not needed for the targets; if ever run, download with `?format=original` (gives the `.csv` names exactly) as a path-only fix.
- Proprietary dependencies: none (R only, no Stata). Package installs: caret pulls many dependencies (Debian `r-cran-caret` exists); install time is the main cost.
- Compute and memory: input is about 0.6 MB of CSVs; the script is vectorised over 589 x 8 matrices. Expected run time under a minute after installs; peak memory well under 1 GB (mostly package loading), so no fallback is needed under the 3 GB limit. R_a to R_c add about 60,000 small matrix comparisons in total, seconds.
- Classification risks: C if the deposited files cannot produce Table A1 (for example if the row-order issue in inconsistency 1 means the table came from a different state of the code or data); D only if both clean runs disagree with an estimate target in a way that changes a ranking or direction criterion. E is unlikely (no compute or proprietary barrier).
