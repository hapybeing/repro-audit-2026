# repro-audit-2026

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23293097.svg)](https://doi.org/10.5281/zenodo.23293097)

Archived on Zenodo: concept DOI (all versions) [10.5281/zenodo.23293097](https://doi.org/10.5281/zenodo.23293097); v1.0.1 version DOI [10.5281/zenodo.23293098](https://doi.org/10.5281/zenodo.23293098). v1.0.1 is an archival release; results are identical to v1.0.

A reproducibility audit of 25 randomly selected 2023 to 2026 papers whose Harvard Dataverse deposit contains R or Python code, run by **Gaurang Kumar** ([@hapybeing](https://github.com/hapybeing)).

Each paper is re-run from the authors' own materials by two separate agent runs (A and a blind B, no shared context, same underlying model family, so not independent human replications), with three pre-registered robustness checks and a code review, then classified A to E. Every number traces to a saved output file, and every table is generated by script.

## Final results
All 25 papers, main counts (`final/all25_counts.json`): A 16, B 0, C 9, D 0, E 0 (n = 25, so no rate claims). With every paper's alternative reading at once: A 13, B 3, C 5, D 1, E 2 (n = 24, because one paper's alternative is exclusion as having no computational target). Both agent runs proposed the same class for 25 of 25 papers, and 122 of 139 pre-registered targets matched the paper at its printed rounding in both runs. Full synthesis: [FINAL_REPORT.md](FINAL_REPORT.md); per-paper table: `final/all25_results.csv`; checks: `final/FINAL_number_check.txt`, `final/FINAL_link_check.txt`.

## Scope
No authors were contacted. Classes describe whether the materials reproduce the paper's numbers; they are not judgements of the research. A class C means the paper could not be checked from the materials the article points to, not that the paper is wrong. "Code observations" are listed as verified or unverified; unverified ones are marked as unverified wherever they appear and are not findings. Batch 1 pre-registration hashes were frozen locally before the runs but first published here together with the results, so that ordering is self-attested; from batch 2 on, hashes are posted before runs.
