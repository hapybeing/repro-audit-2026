## 5. What "open code and data" meant in practice
- The frame filter required only that a dataset contain at least one R or Python code file (by Dataverse content type). It did not check for data files.
- Eligibility criteria E1 to E6 (`selection/screening.csv` columns: E1_article, E2_open_text, E3_no_restricted, E4_no_stata_matlab_spss_sas, E5_size_ok, E6_licence) contain no data-presence criterion. Columns mentioning data, other than the DOI and link: 0. E3 checks that no file is restricted, not that data are present.
- So the presence of the data needed to reproduce the paper was **not** an eligibility criterion. It was assessed only during the audit, where it can lead to class C.
- Batch 1 shows the consequence: 04_PSHE5L's deposit is 14238 bytes titled "Replication Code for: ..." and the batch report records: "04: data came from the authors' OSF page, not the Dataverse deposit (code only). Judged on the deposit alone it would be C; both agents chose A. Flagged for your decision.". 03_3IOGQ8's notebook input `Byonic_results.csv` is recorded as not deposited in its PREREG.md: yes. 01_5BIH0P's production trajectory is recorded as not in the dataset in its PREREG.md: yes.
- Any description of the sample as "papers with open data and code" should read "papers whose Dataverse deposit contains R or Python code".
